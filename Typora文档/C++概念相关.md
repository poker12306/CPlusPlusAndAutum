- ==**C++中的赋值与初始化**==：

​		**`:`（初始化列表）**：是在给变量分配内存的那一瞬间，顺手把初始数据填进去（**初始化**）

​		**`{}`（构造函数体）**：内存早就分配完了，里面的东西都已经出生了，你在这只能对它们进行重新修改（**赋值**）

​		关于赋值操作，需要注意的点是：1.当前内存之前是一个合法值，写入新数据时，要将数据拷贝进来。2.如果	旧对象内部申请了堆内存，必须先delete掉，否则直接覆盖就会出现内存泄漏。

​		**只能被初始化，拒绝被赋值**：const变量和引用变量一生只能被绑定一次

```
int a = 10;
int b = 20;

// 对于 const
const int MAX_SPEED = 100; // 合法：在出生（分配内存）的瞬间完成初始化
const int MIN_SPEED;       // 编译报错！没有初始化
MIN_SPEED = 0;             // 编译报错！const 拒绝被赋值修改

// 对于引用（底层是指针常量）
int& ref = a;              // 合法：初始化，ref 永远绑定了 a 的内存地址
int& ref2;                 // 编译报错！引用必须在出生时初始化
ref = b;                   // 这不是让 ref 绑定 b，而是把 b 的值(20)赋给 a 的内存！
```



- ==**拷贝构造函数的定义**==：

  在程序中，经常使用**已有对象**完成**新对象**的**初始化**，因此需要定义拷贝构造函数，完成这样的功能。而运算符重载=则是完全的**赋值**操作。

  ```c++
  class Image { ... };
  
  Image img1;              // 1. 调用无参构造函数（诞生）
  
  Image img2(img1);        // 2. 调用【拷贝构造函数】（用 img1 克隆出全新的 img2）
  
  Image img3 = img1;       // 3. 极其迷惑！这里调用的依然是【拷贝构造函数】！
                           // 因为 img3 正在“出生”，虽然写了 =，但本质是初始化。
  
  Image img4;              // 4. 调用无参构造函数（img4 诞生）
  img4 = img1;             // 5. 调用【重载赋值运算符 =】！
                           // 因为 img4 早就出生了，这是将 img1 的状态覆盖给已存在的 img4。
  ```

  **深拷贝**和**浅拷贝**的最主要区别就是，当对象的成员变量有堆内存的指针时，浅拷贝用的是已有对象的地址指针，而深拷贝，则会先创建一个新的堆区内存，然后复制已有对象的数据进新的内存区域中。

- ==**Const关键词**==：

  在C++标准中，const真理般的规则是**修饰它左边的东西，如果左边没东西，才修饰右边的东西**。因此

  const int id 和 int const id;在C++中是**完全等价**的！

  当在成员函数末尾加上const时，实际上，在编译器内部，这个常成员函数在全局函数中的函数定义如下：

  ```c++
  void print(ClassType* const this); // this 指针本身不能指别人，但它指向的内存可以改
  //普通成员函数在底层会被转化为带this指针的全局函数
  
  // 想要达到的底层效果：让 this 指向的内存变成只读
  void print(const ClassType* const this);
  ```

  一旦定义了常成员函数，就意味着被传入的对象所指向的this指针不可以指向其他，且当前指向的内存里面的数据不可以被更改。正因为如此，常成员函数才会有如下条条款款，归根到底的就是**常成员函数所传入的那个对象所在的内存被认为是只读**，一旦有可能的越界行为，会出现错误。

  ```c
  //1.不能修改成员变量（因为 this 指向的内容被锁死了）。
  //2.不能调用非 const 函数（因为如果允许调用，那个非 const 函数可能会修改数据，这属于“借刀杀人”，编译器绝对不允许这种漏洞）。
  //3.同名函数构成重载（因为它们的隐藏参数类型不同，一个是 ClassType* const this，另一个是 const ClassType* const this，参数类型不同自然构成重载）。
  //4.const 修饰的常对象只能访问常成员函数；但是，非 const 的普通对象，是完全可以访问常成员函数的！
  ```

- ==**Static关键词**==：

  不管是被static修饰的成员变量还是成员函数，他们均是**纯正的全局变量以及全局函数**，纯正的全局函数即不包含对象的this指针。这二者都**不以对象的存在而存在**。是以**独立**的形式而存在。因此有如下特性：
  
  ```c++
  class Tracker {
      int id;               // 占 4 字节
      static int obj_count; // 静态变量
  };
  //类的大小不以有静态成员变量的存在而有所变化
  
  class Sensor {
      int port;
      static int global_config;
      
  public:
      void normal_func() { port = 1; }
      static void static_func() { global_config = 1; }
  };
  
  // 1. 普通函数：带着 this 指针
  void Sensor_normal_func(Sensor* const this) {
      this->port = 1; // 必须靠 this 寻址
  }
  
  // 2. 静态函数：极其干净的全局函数，根本没有 this！
  void Sensor_static_func() {
      global_config = 1; // 直接操作全局内存（.data段）
  }
  //1.为什么不能访问普通变量？ 因为没有 this 指针！CPU 站在 static_func 里面，手里根本没有对象的内存地址，它怎么可能知道去哪块内存里找 port？
  //2.为什么不能加 const 后缀？ 我们上一题刚聊过，函数后面的 const 是用来修饰隐式的 this 指针的（const ClassType* const this）。现在连 this 指针都没有了，你在这加 const 修饰个寂寞？编译器当然要报错。
  //3.为什么不创建对象也能调？ 因为它就是个挂着 Sensor:: 名字前缀的普通 C 语言全局函数，它的执行根本不需要任何对象的栈或堆内存做支撑
  ```
