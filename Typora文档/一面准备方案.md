## 2. 简历最容易被追问的 10 个点

### 2.1 TensorRT 模型部署：45ms → 15ms

- **为什么问**：这是简历中最亮眼的量化数据，且与算法测试直接相关
- **最可能问**：TensorRT 的 FP16 推理原理是什么？为什么能从 45ms 降到 15ms？瓶颈在哪？
- **继续追问**：YOLOv8s 的模型结构了解多少？迁移学习的微调数据量多大？如何验证推理精度没有下降？

### 2.2 生产者-消费者管线设计

- **为什么问**：体现了并发设计能力，且"级联数据管线"是核心架构
- **最可能问**：条件变量和互斥锁怎么配合？为什么用条件变量而不是信号量？如何避免死锁？
- **继续追问**：管线中有几个生产者几个消费者？背压怎么处理？如果某个模块卡住怎么处理？

### 2.3 推流延迟 120~150ms 是怎么测的

- **为什么问**：测试工程师岗位，对"怎么测"的追问是必考
- **最可能问**：延迟是怎么量化的？测量方法是什么？有没有自动化？
- **继续追问**：1080P@30fps 下 CPU 占用率降低 80% 是怎么做到的？硬件编码 vs 软编码的区别？

### 2.4 ByteTrack 多目标跟踪

- **为什么问**：跟踪算法是感知模块的核心，且涉及卡尔曼滤波和 IoU 匹配
- **最可能问**：卡尔曼滤波的基本原理？级联 IoU 匹配是怎么做的？遮挡后怎么恢复？
- **继续追问**：跟踪 ID 切换（ID Switch）怎么评估？用了什么指标？如果跟踪效果不好你怎么定位问题？

### 2.5 双目测距 ±5% 误差

- **为什么问**：涉及相机标定和立体匹配，且有明确精度指标
- **最可能问**：双目相机标定流程？±5% 误差是怎么验证的？测试数据量多大？
- **继续追问**：标定精度怎么保证？不同距离段的误差分布？如果误差超标怎么排查？

### 2.6 ROS1 多传感器时间同步 ≤25ms

- **为什么问**：自动驾驶数据融合的核心问题，且你用了近似时间同步
- **最可能问**：message_filters 的 approximate time sync 原理？25ms 同步精度怎么验证？
- **继续追问**：3 类传感器的频率分别是多少？如果某个传感器丢帧怎么办？同步队列大小怎么设？

### 2.7 AEB 触发准确率 100%

- **为什么问**：AEB 是安全关键功能，100% 准确率会被质疑
- **最可能问**：测试场景有哪些？8 种场景是怎么设计的？100% 是在什么条件下测的？
- **继续追问**：AEB 的决策逻辑是什么？误触发率呢？有没有做过边界条件测试？

### 2.8 Dora-rs 中间件 vs ROS

- **为什么问**：国产中间件不常见，面试官会好奇你为什么选它、了解多深
- **最可能问**：Dora-rs 和 ROS 的核心区别是什么？为什么选 Dora-rs？
- **继续追问**：Dora-rs 的通信机制？零拷贝是怎么实现的？相比 ROS 的性能优势？

### 2.9 3×24 小时稳定性测试

- **为什么问**：测试岗位对稳定性验证很关注
- **最可能问**：怎么监控内存泄漏？用了什么工具？CPU 占用率怎么统计？
- **继续追问**：有没有用 Valgrind / AddressSanitizer？有没有做压力测试？异常恢复机制？

### 2.10 "车-云-端"通信架构

- **为什么问**：涉及 TCP 透传和 HTTP 协议，且是独立完成的服务端
- **最可能问**：TCP 粘包怎么处理？HTTP 和 TCP 的分工？车辆控制指令的协议设计？
- **继续追问**：断线重连机制？多客户端怎么管理？安全性怎么保证？

## 4. 项目追问模拟

### 项目一：多任务视觉感知及远程控制系统

**面试官：你这个项目用了生产者-消费者模型来设计管线，能具体说一下管线的结构吗？有几个模块，数据怎么流转的？**

我需要回答的重点：
- 管线是级联的：视频采集（生产者）→ AI 推理（消费者+生产者）→ 目标跟踪 → HUD 渲染 → 推流
- 每一级之间用条件变量 + 互斥锁做线程间通信
- 缓冲队列的作用：解耦各模块，避免某个慢模块拖慢整体
- 30 FPS 的吞吐是怎么保证的

可能继续追问：
- "如果推理模块突然变慢，比如从 15ms 变成 100ms，管线会怎样？"
  → 需要回答背压机制：队列满了怎么办？丢帧还是等待？设计上的权衡
- "条件变量为什么不用信号量？"
  → 条件变量可以配合复杂条件判断，信号量更适合简单的计数场景

**面试官：TensorRT 的 FP16 推理，从 45ms 降到 15ms，这个优化具体做了什么？**

我需要回答的重点：
- FP16 vs FP32：精度减半，计算量减半，GPU Tensor Core 可以加速
- TensorRT 的优化：层融合、Kernel 自动调优、内存优化
- YOLOv8s 模型导出 ONNX → TensorRT engine 的流程
- 45ms 是 PyTorch 原始推理，15ms 是 TensorRT FP16 推理后的结果

可能继续追问：
- "怎么验证 FP16 精度损失可接受？"
  → 需要说 mAP 对比、在验证集上的结果差异
- "为什么不用 INT8？"
  → INT8 需要校准数据集，精度损失更大，FP16 是精度和速度的平衡

**面试官：推流延迟 120~150ms，这个数字是怎么测出来的？**

我需要回答的重点：
- 测量方法：发送端打时间戳，接收端对比本地时钟（NTP 同步）
- 或者：在同一网络环境下，发送端画面显示计时器，接收端截图对比
- 端到端延迟 = 采集延迟 + 编码延迟 + 网络传输延迟 + 解码延迟

可能继续追问：
- "有没有做过不同网络条件下的测试？"
- "如果延迟突然飙到 500ms，你怎么排查？"

**面试官：3×24 小时稳定性测试，你用什么工具监控内存泄漏？**

我需要回答的重点：
- 监控工具：top / htop 看内存趋势，/proc/[pid]/status 看 RSS
- 如果用过 Valgrind / AddressSanitizer 要说
- 连续运行中关注：内存是否持续增长、是否有突然的内存跳变
- CPU 占用率的统计方法

可能继续追问：
- "你有没有写过自动化监控脚本？"
  → 这就是测试开发的核心能力，需要展示脚本编写能力

### 项目二：自动驾驶在环仿真系统

**面试官：ROS1 的近似时间同步，能说一下原理吗？为什么精度能到 25ms？**

我需要回答的重点：
- message_filters::ApproximateTimeSynchronizer 的原理：基于时间戳的消息队列，在时间窗口内匹配最近的消息
- 25ms 是怎么验证的：记录同步后消息的时间戳差异，统计分布
- 3 类传感器的频率和时间戳来源

可能继续追问：
- "如果某个传感器丢帧了，同步会怎样？"
  → 队列超时丢弃，或用上一帧补全
- "同步队列大小怎么设？设太大有什么问题？"
  → 太大增加延迟，太小容易丢消息

**面试官：AEB 触发准确率 100%，这个测试是怎么设计的？**

我需要回答的重点：
- 8 种场景的设计思路：基于封闭园区的真实工况
- 每种场景的触发条件和预期行为
- 准确率 = 正确触发次数 / 应触发次数
- 100% 是在有限场景下测的，不代表所有场景

可能继续追问：
- "误触发率呢？有没有不该触发但触发了的情况？"
- "如果要在开放道路上测试，测试方案会怎么变？"
- "你怎么判断 AEB 触发的时机是否合适？太早或太晚怎么评估？"

## 5. 准备优先级

### 如果只有 1 天准备

**必须做到（核心保命）：**

1. **项目讲清楚**（最重要）：把两个项目的技术方案、你的角色、关键数据、遇到的困难和解决方案，每个用 3~5 分钟讲清楚。面试官 80% 的时间会花在项目上。
2. **Linux 基本命令**：`top`、`ps`、`grep`、`awk`、`netstat`、`htop`、`df`、`free` — 能说出用途和常用参数。
3. **多线程基础**：互斥锁、条件变量怎么用？生产者-消费者模型怎么写？死锁是什么？
4. **TCP 基础**：三次握手、四次挥手、TCP vs UDP 区别。
5. **算法题**：刷 2~3 道链表和二叉树的 Easy 题，手写代码不卡壳。

**可以先跳过：**
- Python 高级特性（GIL、装饰器等 — 如果你 Python 不熟，先不要硬背，面试官一追问就露馅）
- 自动驾驶深度知识（了解感知-规划-控制流程即可）
- 设计模式、操作系统深度题

**心态：** 一面主要看你基础扎不扎实、项目是不是自己做的。能把自己做的东西讲清楚 > 背一堆八股。
